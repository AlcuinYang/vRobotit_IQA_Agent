# 画质评估的需求侧调研：谁需要、什么场景需要、需要什么样的评估
---

## 0. 一个贯穿全文的判断

画质评估的需求不是按"行业"分的，是按**四个问题**分的：

1. **评的是设备，还是评这张图？**
2. **评完之后，还来不来得及补救？**
3. **结果给谁看——工程师、业务系统，还是拍照的人？**
4. **这个判断需不需要被仲裁？（会不会有人不服）**

后面所有的行业差异，最终都能归到这四个问题上。

# 第一部分 · 什么人、什么厂家需要

## A 类 · 造影像设备的人

### A1 手机厂、模组厂、传感器与镜头厂

- **谁**：手机厂影像部门、camera 模组厂、sensor 与镜头供应商、ISP 算法团队。
- **为什么需要**
  1. **调优要有靶子**：ISP 有成百上千个旋钮，改一个参数是变好还是变坏，需要能重复测量的数。
  2. **供应链要有验收语言**：手机厂和模组厂之间必须有共同认可的标准，否则来料好坏无法仲裁。
  3. **对外要有排名**：DXOMARK 分数直接进发布会。
- **需要什么样的评估**：评的是**设备**不是图片，**必须有受控输入**（标准图卡 + 标准灯箱）；要属性级、可复现、可跨时间对比；不需要自然语言。关键维度：锐度/MTF、噪声、动态范围、色彩保真、**3A（自动曝光、自动白平衡、自动对焦）**、眩光、几何畸变、纹理保留。
- **代表产品**
  - **DXOMARK Analyzer**——测试软件套件，12 个测量类目，配套图卡、灯箱、六足机器人；分 FREE / GUI / API / PREMIUM 四档；全球装机 150 多个实验室
  - **Imatest**——更工程师自助的一档，13 个以上质量因子、30 多种图卡；**IT 产品线专为产线自动化做，提供四种编程接口**
  - **Image Engineering iQ-Analyzer-X**——德国方案，结果存数据库支持跨实验室比对
  - **高通 Chromatix / Chromatix Light**——**调优工具**（暴露旋钮：AWB、色调、色彩校正矩阵、饱和度、对比度、降噪、锐化、AEC）
  - **eInfochips、Image Quality Labs 等第三方 ISP 调优服务商**
- **一条行业惯例**：**调优工具由芯片厂给，评测工具由第三方给，两者刻意分离**——裁判不由选手当。

### A2 车载摄像头与 ADAS

- **谁**：车厂（OEM）、Tier 1、车载 camera 与 ISP 供应商。
- **为什么需要**：车载的图不是给人看的，是**给算法看的**，画质缺陷会直接变成感知失效，是安全问题；而且 OEM 与 Tier 1 之间必须有共同语言来定验收。
- **需要什么样的评估**
  - 有明确国际标准 **IEEE 2020-2024**，284 页，**第一个国际公认的车载相机画质性能标准**，2016 年成立工作组，300 多位行业专家参与。
  - KPI：**对比度传递准确性（CTA）、对比信噪比（CSNR）、闪烁抑制概率（MMP）、动态范围、眩光、噪声、空间频率响应（SFR）、几何标定**。
  - 与消费影像的关键差异：**闪烁（LED 交通灯和车灯）和极端动态范围是车载独有的硬指标**，"好不好看"完全不重要。
- **代表产品**：**Image Engineering** 的车载测试实验室与 IEEE P2020 KPI 测试方案；**Imatest 车载测试方案**。两家都把"符合 IEEE 2020"做成了卖点。

### A3 安防监控：设备侧与运维侧是两个需求

> **这一类是上一轮竞品调研整个漏掉的，而且它的维度与实验室能力重合度最高。**

- **设备侧**
  - 谁：海康威视、大华、宇视、天地伟业等。
  - 为什么：出厂与招标要对标准（**IEC 62676-5** 定义了摄像机的数据规格与画质性能）。
  - 代表产品：**正印科技 CIQT**——针对国内安防标准优化的画质分析软件，同时支持国际画质标准。
- **运维侧（需求更刚性）**
  - 谁：各地安防集成商、平安城市运维方、行业用户的视频专网。
  - 为什么：一个城市几万路摄像头，**镜头脏了、失焦了、偏色了、被遮挡了、花屏了，没人会主动发现**，但出事调录像时才发现就晚了。
  - **需要什么样的评估**：**定期巡检每一路视频流 + 自动生成故障工单**。这是"批量、无人值守、结果进工单系统"的典型。
  - **代表产品形态：VQD（视频质量诊断）系统**，是安防行业的标准品类。典型能力清单包括**亮度检测、清晰度检测、偏色检测、对比度检测、噪声检测、抖动检测、冻结检测、遮挡检测、马赛克检测、花屏检测、蓝屏检测、场景变换检测，并自动抓拍告警**。国内的视频智能运维平台大多支持 GB/T 28181 接入，兼容海康、大华、科达等主流设备。
  - **值得注意**：这份维度清单里的亮度、偏色、对比度、清晰度、噪声，**和实验室的属性几乎一一对应**，只是它服务的是运维告警，不是评"好不好看"。

### A4 医疗影像设备与医院放射科

- **谁**：影像设备厂商；医院放射科的**质控岗**。
- **为什么需要**：图像质量直接影响诊断，而且**是被监管的**——《放射影像专业医疗质量控制指标（2024 年版）》划定七大核心管控指标，《中国医学影像质量控制指南（2026 版）》等行业准则同步落地。
- **需要什么样的评估**
  - **要前置到拍摄当场**，秒级反馈技师，当场重拍。
  - 维度是医学专用的：伪影、清晰度、**摆位/定位准确性**、曝光参数合规、对比度、噪声。
  - **结果必须能进质控报表**——是管理指标，不只是技术指标。
- **代表产品**：**联影智能 影像检查智能质控系统**——AI 自动图像质控，覆盖乳腺钼靶、DR、CT 等部位，**在设备端实现质控前置，秒级反馈技师**（厂商材料，覆盖范围待核实）。

## B 类 · 用影像跑业务的人

### B1 身份核验、银行与保险

- **谁**：KYC 厂商、银行远程开户系统、保险自助定损、政务人脸库。
- **为什么需要**：图像不合格 → OCR 失败、人脸比对失败 → 转人工复核 → 成本飙升、转化率下降。**这是所有场景里"画质差"的代价最直接可算的一类。**
- **需要什么样的评估**
  - **必须在用户还举着手机的时候给结果**：检测到翻拍、模糊、曝光过强、黑白等问题，自动剔除不合格件并**在前端实时提示重新拍摄**。
  - **输出是过/不过，不是分数**。
  - **必须说清楚为什么不过，并给出怎么改**。
  - **要有权威依据**：人脸走 ISO/IEC 29794-5，指纹走 NFIQ 2，**质量分是按"会不会影响识别率"校准的**。
  - 保险定损侧的要求更业务化：不只清晰，还要**拍全、拍正、车牌可辨、碰撞位置多角度**——**"构图合规"本身就是质量要求的一部分**。
- **代表产品**
  - **OFIQ**——德国 BSI 开发的 ISO/IEC 29794-5 开源参考实现，统一质量分 + 25 到 27 个质量分量，分量还分成"采集相关"与"主体相关"两组
  - **NFIQ 2**——NIST 的指纹图像质量，开源，质量分与识别性能校准
  - **Regula Document Reader SDK**——三项检查（分辨率、对焦、眩光），输出三值枚举而不是分数
  - **Veriff Assisted Image Capture / Jumio Course Correction**——**拍摄过程中实时指引用户当场纠正**
  - 国内：**蚂蚁金服「定损宝」**等车险图像定损应用；银行侧的开户材料图像质检（翻拍、模糊、过曝检测 + 实时提示重拍）

### B2 测绘与遥感

- **谁**：测绘单位、自然资源系统、卫星影像生产方与采购方。
- **为什么需要**：影像是**成果**，要验收、要付款、要归档，必须有可仲裁的质量结论。
- **需要什么样的评估**
  - 走国家标准：**GB/T 24356-2023《测绘成果质量检查与验收》**规定了分批抽样、质量元素与错漏分类；另有《数字航天摄影测量成果质量检查与评价规范》，以及在制的《实景影像数据产品质量检查与验收》。
  - 形态是**抽样检查 + 错漏分类 + 质量评分**，结论进验收报告。
  - **几何与辐射质量并重**（云量、清晰度、色彩一致性、几何精度、接边），这是通用 IQA 不涉及的。
- **代表产品**：**航天宏图 PIE 系列**（PIE-Basic、PIE-Ortho、PIE-Lidar 等），覆盖遥感影像全流程处理，其中含数据质检环节（**具体质检模块的能力范围待核实**）；机构侧有**国家测绘产品质量检验测试中心**，使用高精度影像集、地形数据集与自有质检软件开展检验。

### B3 档案、图书馆与文博数字化

- **谁**：档案馆、图书馆、博物馆，以及承接数字化外包的服务商。
- **为什么需要**：数字化是一次性、不可逆的，**不达标意味着整批重扫**；采购方要验收。
- **需要什么样的评估**
  - 三套并行标准：美国 **FADGI**（四星分级）、欧洲 **Metamorfoze**、国际 **ISO 19264-1**（A/B/C 级）。对应关系：FADGI 四星 = ISO 19264-1 A 级 = Metamorfoze Full。
  - 四星要求：**极高采样效率（锐度）、极低色度误差（色彩准确性）、高光照均匀性、几乎为零的色彩配准偏差**。
  - **这是"画质评估被写进采购合同条款"最典型的一类**——合同里直接写达到几星。
- **代表产品**
  - 测量软件：**Image Engineering iQ-Analyzer-X**，并专门出了 **CH（Cultural Heritage）文化遗产版**，功能裁剪、价格更低
  - 设备与服务：**Image Access、Zeutschel / book2net** 等扫描仪厂商把"符合 FADGI / ISO 19264"写进产品说明；**The Crowley Company、DT Heritage** 等服务商提供 **FADGI / Metamorfoze 性能报告**作为交付物

### B4 电商平台、图库与内容平台

- **谁**：电商平台的商品图审核、图库、UGC 平台的内容准入。
- **为什么需要**：质量是准入门槛，也是平台体验的下限；图库还多一层——不合格的图卖不出去，反而占用审核资源。
- **需要什么样的评估**：**分维度的规则 + 明确的拒绝理由**。
- **代表产品与规则**
  - **Shutterstock**——覆盖 14 项以上维度（对焦、曝光、噪声、颗粒、压缩伪影、色带、像素化、构图、后期痕迹、传感器脏点、反光、**白平衡**等），审稿人在 100% 原图比例下逐张看，拒稿时给出类别，每类配一篇知识库文章讲怎么避免
  - **Adobe Stock**——锐度、曝光、分辨率、噪声、压缩、伪影，并指出成因（高 ISO、过度后期、传感器灰尘、卷帘快门）
  - **Amazon 主图规范**——更偏形式合规：最长边 ≥1000px、纯白底、商品占比 ≥85%、无水印
  - 机审侧：**Sightengine**（质量分 + 锐度/对比度/亮度）、**Everypixel**（**区分 UGC 与图库两个模型**）

## C 类 · 分发影像的人

### C1 流媒体、广电与视频云

- **为什么需要**：① **交付验收**——片子交给平台要过 QC；② **成本**——码率降一点就是真金白银，但不能让用户看出来；③ **运营可见性**——体验差在哪一环要能定位。
- **需要什么样的评估**
  - 交付侧要**合规报告**：格式合规、黑场静帧、响度、伪影，自动 QC 与人工 QC 在同一流程里。
  - 成本侧要**逐帧的感知质量约束**，指标不卖钱，是编码器的一部分。
  - 运营侧要**属性级 + 影响归因**。
- **代表产品与规范**
  - 交付规范：英国 DPP 的 **AS-11**（BBC、ITV、Sky、Channel 4 等共同约定，另有澳新、北欧、北美变体）；**Netflix** 要求 IMF 包先过 **Photon** 工具校验，并做**光敏癫痫（PSE）检测**与大范围伪影检查
  - QC 产品：**Interra BATON**（含基于神经网络的质量检查，支持自动 + 人工混合 QC）、**Telestream**、**Venera**（专门做面向 Netflix 等交付规范的合规检查）
  - 感知度量：**IMAX SSIMPLUS**（Viewer Score 0–100，**设备感知**——同一段视频在电视和手机上给不同分）、**Beamr CABR**（帧级挑"码率最低但感知不劣化"的编码）
  - QoE：**Mux Data**（整体体验 0–100 拆成四个子分，外加 **Negative Impact Score** 直接排出哪项伤害最大）、**Conviva**
  - CDN 侧：**Cloudinary q_auto**（best/good/eco/low 四档 + 自研 **SSIMULACRA 2** 校验）、**imgix**、**Uploadcare Adaptive Quality**

### C2 短视频与直播平台

- **为什么需要**：UGC 上传素材质量参差，**低质内容既伤体验又浪费推荐流量和转码资源**。
- **需要什么样的评估**：**无参考打分 → 卡阈值 → 低质进增强流程或降权**，全自动，不需要解释。
- **代表产品**
  - **抖音集团的自研画质评估工具**——用于筛查低质内容，配合画质增强能力搭建自动化处理流程
  - **火山引擎 veImageX 画质评估**（大众美学、噪声强度、纹理丰富度、色调均衡四项）与 **VQScore**（无参考视频质量 0–100，对标 VMAF 但不需参考）
  - 修复增强路线：**腾讯云画质重生**、**阿里云窄带高清**——**不评价，直接修**

## D 类 · 生产影像内容的人

### D1 职业摄影师与影楼

- **为什么需要**：一场婚礼 3000–5000 张，人工选片 6–10 小时。**买的是时间。**
- **需要什么样的评估**：模糊、闭眼、重复、曝光问题、构图；输出是**分桶和排序**；**敏感度必须可调**；**完全不需要改进建议**——照片已经拍完了。
- **代表产品**：**Aftershoot**（$10/月不限张数，分桶 + 敏感度滑块）、**Narrative Select**（对焦评分 0–100、眼睛状态）、**Imagen AI**（$0.05/张，**用你自己 3000 多张历史修片训练出你的风格**）、**FilterPixel**（单次检查八项信号，含曝光质量）、**Lightroom 辅助选片**（**可展开看每张的评分明细**）、**Photo Mechanic**（完全没有 AI，只卖浏览速度，永久 $299 起）。

### D2 影视后期与内容制作方

- **为什么需要**：交付要过平台 QC，素材要筛。
- **需要什么样的评估**：面向交付规范的合规检查，以及伪影、抖动、闪烁等技术缺陷检测。
- **代表产品**：同 C1 的 **Interra BATON、Telestream、Venera**。

### D3 摄影爱好者

- **为什么需要**：**想变得更好。**
- **需要什么样的评估**：**这是唯一一类"解释和建议本身就是全部商品"的需求**——属性级分数 + 每项一段文字 + 具体改进动作。
- **代表产品**：**Adobe Project Indigo**（2026-07 更新，点评覆盖取景、光线、色彩、情绪冲击，给重拍建议并在取景器里指认干扰物，底层用谷歌 Nano Banana）、**PhotoCritic、Photo Critique、Evalens、PixMentor** 等一批点评 App（六维打分 + 每维文字 + 具体动作，**都没有任何权威背书**）。

## E 类 · 训练模型的人

- **谁**：AI 数据团队、自动驾驶数据闭环团队、大模型语料团队。
- **为什么需要**：**低质数据污染模型**，而且几百万张的规模无法人工看。
- **需要什么样的评估**：**异常检测，不是质量评分**；交互范式是**直方图 + 可拖动阈值滑块 + 批量打标签**。**它不回答"这张图好不好"，它回答"这批图里哪些是异常值"。**
- **代表产品**：**Voxel51 FiftyOne Data Quality**（亮度、模糊、极端宽高比、信息熵异常、近似重复、完全重复六类；**并且有 agent skills 生态，画质检测已被封装成 skill**）、**Cleanlab CleanVision**（七类，同时给布尔判定和 0–1 严重度）、**Labelbox**。

# 第二部分 · 什么场景和应用需要

把场景按**影像生命周期**排开，需求性质随环节明显变化：

| 环节 | 典型场景 | 为什么需要 | 需要什么样的评估 | 建议 | 代表产品 |
|---|---|---|---|---|---|
| **① 设备研发与验收** | ISP 调优、模组来料、车载与安防选型 | 调优要靶子、供应链要验收语言 | 受控输入下的属性级测量，可复现、可跨时间对比 | 以咨询服务形式给 | DXOMARK Analyzer、Imatest、iQ-Analyzer-X |
| **② 采集当场** | KYC 拍证件、医院拍片、保险定损拍照 | 不合格要重拍，**人还在现场** | 实时、二值判定、指出具体问题 | **必须给，是核心价值** | Veriff、Jumio、Regula、联影智能质控 |
| **③ 入库准入** | 图库投稿、电商商品图、UGC 上传 | 质量是准入门槛 | 分维度规则 + 明确的拒绝理由 | 给（知识库形式） | Shutterstock / Adobe Stock 规则、Sightengine、Everypixel |
| **④ 生产加工** | 摄影选片、批量修图、粗剪 | 省人工时间 | 分桶 + 排序 + **阈值可调** | **不给**（来不及了） | Aftershoot、Narrative、FilterPixel、Lightroom |
| **⑤ 交付验收** | 测绘验收、档案数字化验收、节目交付 | 要付款、要归档、要仲裁 | 抽样 + 分级 + 合规报告，**必须对标准** | 不给，给通过/不通过 | GB/T 24356、FADGI/ISO 19264、AS-11、Interra BATON |
| **⑥ 传输分发** | 转码、CDN 优化、码率决策 | 省带宽且用户察觉不到 | 感知质量差值，机器内部使用 | 不给（直接替你决定） | Cloudinary q_auto、Beamr CABR、SSIMPLUS |
| **⑦ 运维巡检** | 安防摄像头巡检 | 几万路设备无人盯着 | **异常检测 + 自动工单** | 给的是故障类型 | VQD 视频质量诊断系统、视频智能运维平台 |
| **⑧ 训练与评测** | 数据集清洗、模型评测 | 低质数据污染模型 | 异常检测 + 阈值 + 批量操作 | 给的是操作 | FiftyOne、Cleanlab |
| **⑨ 学习与提升** | 摄影点评 | 想变好 | 属性级 + 每项文字 + 具体动作 | **给，且是全部商品** | Adobe Project Indigo、PhotoCritic、Evalens |

**这张表最重要的一条规律：**

> **建议只在环节 ② 和 ⑨ 有价值。**
> ② 是"人还在现场，来得及重拍"；⑨ 是"用户买的就是教学"。
> 其余环节要么来不及，要么用户根本不想学，所以商业产品一律不给建议，而是**直接替你决策或直接替你修好**。

# 第三部分 · 横向归纳

## 3.1 需求的五个变量

| 变量 | 取值 | 决定了什么 |
|---|---|---|
| **评估对象** | 设备 / 单张图 / 一批图 / 一条流 | 要不要受控输入（图卡与灯箱） |
| **时机** | 拍摄中 / 入库 / 加工 / 交付 / 分发 / 训练 | **要不要给建议** |
| **判定形态** | 一个分 / 阈值过不过 / 枚举结论 / 分维度报告 | 结果怎么被下游使用 |
| **依据强度** | 无 / 厂商自定 / 行业标准 / 国际标准 + 第三方评测 | 能不能被仲裁 |
| **结果给谁看** | 工程师 / 业务系统 / 运维工单 / 终端用户 | **要不要说人话** |

**"要不要说人话"完全由最后一个变量决定**：给工程师看就给曲线和数值（Imatest、Analyzer），给系统看就给枚举和阈值（Regula、Sightengine），给运维看就给故障类型和工单（VQD），**只有给终端用户看时才需要自然语言**（Project Indigo、点评 App）。

## 3.2 谁需要属性级，谁只要一个数

**需要属性级**：设备研发调优（定位该调哪个模块）、采集合规（告诉用户改什么）、交付验收（标准本身分维度写）、运营归因（Mux 模式）、**运维巡检（故障类型就是维度）**。

**只要一个数**：内容筛选与低质过滤（抖音、FiftyOne）、传输优化（Cloudinary）、平台机审准入。

## 3.3 具体维度的需求分布

| 维度 | 谁在要（举例） |
|---|---|
| **锐度 / 模糊** | **所有人**。唯一一个全行业、全环节都要的维度 |
| **噪声** | 设备厂、图库审核（头号拒稿理由之一）、医疗、车载、视频、VQD |
| **曝光 / 亮度** | 设备厂 AE 调优、KYC（过曝检测）、医疗、图库、摄影选片、FiftyOne、**VQD 亮度检测** |
| **白平衡 / 偏色** | **设备厂 AWB 调优（高通 Chromatix）、图库（Shutterstock 独立拒稿理由）、VQD 偏色检测**——但**公开云 API 全线不提供** |
| **对比度 / 动态范围** | 车载（极端动态范围是硬指标）、设备厂、档案数字化、VQD |
| **色彩准确性** | 档案文博（色度误差是分级指标）、电商、印刷、医疗 |
| **几何 / 畸变** | 车载、测绘、档案数字化、文档扫描 |
| **闪烁** | **车载独有的硬指标**（LED 灯源） |
| **构图 / 拍全拍正** | KYC、保险定损、电商主图、摄影 |
| **美学** | 图库、摄影、UGC 平台、国产云 API（腾讯、百度、火山都提供） |

## 3.4 需求强度与付费意愿

1. **能直接算出钱的**：转人工复核成本（KYC）、带宽账单（CDN）、返工重扫（档案）、选片工时（摄影）——**最爽快**
2. **合规刚性的**：医疗质控、测绘验收、节目交付、车规——**不做不行，但预算受体制约束**
3. **供应链仲裁的**：手机与车载来料验收——**客单价最高，客户数量少**
4. **运维成本型**：安防 VQD——**采购方是集成商，通常打包进运维平台**
5. **体验相关的**：平台低质过滤——**做的人多，但通常自研不外采**
6. **教学与兴趣**：摄影点评——**单价低，靠量**

## 4. 对我们的直接意义

1. 我们的能力形态（**单张图 + 属性级 + 文字解释**）对应的是环节 ② 和 ⑨，但当前使用场景是"图已拍完"，属于环节 ④——**正是商业上一律不给建议的那个环节**，与"只描述不建议"的决定一致。
2. 需求最刚性的几类（KYC、医疗、测绘、档案、车载）有个共同点：**有标准、有验收、有仲裁需求**，这正是我们最缺的一环。
3. **安防 VQD 是这轮最意外的发现**：它的维度（亮度、偏色、对比度、清晰度、噪声）与实验室能力几乎一一对应，但它服务的是运维告警，输出进工单系统。**这说明同一组属性，换一个交付形态就是完全不同的产品。**
4. **白平衡再次被确认处在特殊位置**：设备厂、图库、安防运维都在要，公开 API 却没人提供。
5. **模糊是全行业唯一的共同维度**，我们的空白正好落在这里。

## 5. 局限与待核实

- 国内标准（GA/T 1400、GB/T 28181、IEC 62676-5、GB/T 24356-2023、放射影像质控指标）**只核到名称与适用范围，未逐条查验条款**。
- **VQD 的能力清单来自视频平台与运维厂商的技术材料，不是某一家的官方产品规格**；各家实际支持的检测项会有出入。
- 医疗 AI 质控的覆盖范围、航天宏图 PIE 的质检模块能力，**均来自厂商材料，属厂商声称**。
- 抖音自研画质评估工具**只有官方技术文章层面的描述**，指标与阈值未公开。
- 保险定损的拍照要求来自保险公司科普材料，**不同公司口径可能不同**。
- 手机与车载供应链的实际验收条款属商业机密，本文只能从公开标准与测试厂商的产品说明反推。
