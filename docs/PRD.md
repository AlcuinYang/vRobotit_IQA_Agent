## 1. 项目定位

**一句话**：IQAgent 是一个承载实验室图像质量评价能力的框架，用来把实验室已有的模型集中呈现出来，并在对外交流时展示实验室的能力。

**目的**
- 给实验室过往项目沉淀的模型、已发表论文中的模型，提供一个统一的承载平台。
- 在与外界交流时，用它现场展示实验室的能力。

**原则**
- **框架为主**：agent 本身不追求强大的能力，够用即可。它的价值在于把实验室的模型接进来、把结果呈现清楚。
- **实验室模型 + 闭源 API**：闭源 API 作为 agent 的**大脑**，负责理解请求、分工、调用工具、整合结果和撰写报告。实验室没有模型的属性，以后可以通过安装 skill、由闭源 API 来补充。这样，框架的整体能力会随着闭源 API 的进步一起增强。
- **判断标准**：一项需求要不要做，首先看它是否有助于"把实验室的模型接进来、呈现清楚"。

## 2. 用户与使用场景

| 角色 | 是谁 | 关心什么 |
|---|---|---|
| 演示者 | 实验室成员 | 在对外交流时，能稳定、顺畅地展示实验室模型的能力 |
| 观众 | 访客、合作方 | 看得懂结果：这张图质量怎么样、哪些方面好、哪些方面有问题 |
| 接入者 | 模型作者本人 | 能把自己的模型放进框架，而不需要了解 agent 内部如何运作 |

**场景 A：对外交流时现场评估一张图**
演示者（或访客）上传一张图，要求评估图像质量，得到各项分数和一段报告，需要时导出报告。

**场景 B：模型作者接入模型**
实验室有新项目或新论文产出了模型，作者本人把它接入框架，之后用户就能在对话中用到这个能力。

## 3. 本阶段范围

### 3.1 框架中的角色分工

| 组成 | 由谁承担 | 负责什么 |
|---|---|---|
| 大脑 | 闭源 API | 理解请求、分工、调用工具、整合结果、撰写报告 |
| 属性评估 | 实验室模型 | 给出分数、偏向、文字解释 |

### 3.2 覆盖的能力

| 能力 | 输出 |
|---|---|
| 整体质量 | 分数 + 文字解释 |
| 曝光 | 分数 + 偏向 |
| 对比度 | 分数 |
| 白平衡 | 分数 + 偏向 |
| 色彩 | 分数 |

### 3.3 本阶段不做

| 内容 | 处理方式 |
|---|---|
| 实验室没有模型的属性（如模糊、噪声、压缩伪影） | 以后通过接入模型或安装 skill 补充 |
| 美学、构图 | 以后作为扩展接入，例如用户明确说"给我进行美学打分"时调用 |
| 复杂的需求拆解（理解用户为什么问） | 从一句话里拆不出更多信息，本质是伪需求；以后通过对话实现 |
| 问题模糊时的连续追问 | 以后通过对话实现，需要单独深入讨论 |
| 针对图中局部区域的问题 | 暂不做 |
| 改进建议 | 本阶段报告只做描述 |
| 在结论旁标注出自哪个模型、论文或项目 | 不需要 |

## 4. 功能需求

### 4.1 理解评估请求：按属性简单拆分

| 编号 | 需求 |
|---|---|
| F1 | 用户笼统地要求评估图像质量时（如"给我评估一下这张图的图像质量"），评估**整体质量和本阶段覆盖的全部属性** |
| F2 | 用户点名某个属性时（如"曝光怎么样"），**只评估该属性** |
| F3 | 用户问到尚未接入的属性时（如"噪点多不多"），**如实说明暂不支持**，不对该属性给出任何判断 |

### 4.2 结果呈现：分数 + 报告

| 编号 | 需求 |
|---|---|
| F4 | **分数统一换算**到同一个分制后展示，不展示模型的原始分数 |
| F5 | **报告**由大脑（闭源 API）把整体质量模型的文字解释和各属性分数整合起来，重写成一段话（实验室模型本身不产出报告，所以采用这种方式） |
| F6 | 报告**只做描述**：整体质量如何，各属性表现如何，哪些方面有问题；**不给改进建议** |
| F7 | **曝光和白平衡要说出偏向**：曝光说明偏暗还是偏亮，白平衡说明偏暖还是偏冷 |
| F8 | 报告内容**只能基于模型的输出**，不得加入模型没有给出的判断，也不得夸大模型结论的程度 |
| F9 | **一致性**：同一张图重复评估，分数相同，报告对各属性好坏的定性一致 |
| F10 | 某个属性的模型调用失败时，报告中说明"该项本次未取得结果"，其余属性照常给出 |
| F11 | 报告**可以导出** |

**呈现示意**（数值和措辞均为虚构，仅用于说明形式）

> | 项目 | 分数 |
> |---|---|
> | 整体质量 | 62 |
> | 曝光 | 48（偏暗） |
> | 对比度 | 71 |
> | 白平衡 | 80（无明显偏色） |
> | 色彩 | 66 |
>
> 这张图整体质量中等，暗部细节保留一般。分项来看，曝光得分偏低，画面偏暗，是主要的扣分项；对比度和色彩表现正常；白平衡良好，没有明显偏色。

其中"暗部细节保留一般"来自整体质量模型的文字解释；"偏暗""没有明显偏色"来自曝光和白平衡模型给出的偏向；其余内容由各属性分数整理而来。

### 4.3 能力扩展

| 编号 | 需求 |
|---|---|
| F12 | **更新已有属性的模型**：同一属性出了新模型时，直接替换旧模型，不保留旧版本 |
| F13 | **新增属性**：接入后，用户问到该属性时即可调用 |
| F14 | **新增用法**：可以增加新的使用方式（新的 skill），不局限于"评估一张图" |
| F15 | **由模型作者本人完成接入**，接入过程不要求作者了解 agent 内部如何运作 |

### 4.4 过程可查看

| 编号 | 需求 |
|---|---|
| F16 | **每次评估的过程可以回看**：调用了哪些模型、各模型的原始输出、大脑如何整合成报告。用于实验室成员排查问题（例如报告出现失真时，判断是模型输出本身如此，还是大脑改写时加入的）。这是面向实验室成员的记录，**不在给观众的呈现中展示**，与 F4"不展示原始分数"、§3.3"不在结论旁标注出处"不冲突 |

## 5. 典型流程（用户视角）

**流程 1：笼统评估一张图**
1. 上传图片，输入"帮我评估一下这张图的图像质量"
2. 系统评估整体质量和曝光、对比度、白平衡、色彩
3. 展示统一分制的分数和一段报告
4. 需要时导出报告

**流程 2：询问单个属性**
1. 上传图片，输入"这张图的白平衡怎么样"
2. 系统只评估白平衡
3. 展示白平衡的分数，并说明是否偏暖或偏冷

**流程 3：问到未接入的属性**
1. 用户问"这张图噪点多吗"
2. 系统说明目前还不支持噪声评估，不给出判断
3. 可以告知目前支持哪些评估项

**流程 4：模型作者接入新能力**
1. 作者准备好自己的模型
2. 作者本人按接入方式把模型放进框架
3. 接入后，用户在对话中问到该属性时即可使用

## 6. 约束与前提

- 基于 DeepSeek Harness 平台搭建。
- 闭源 API 作为 agent 的大脑。
- 实验室的属性模型已部署为 API，可直接调用。
- 曝光和白平衡模型需要输出偏向信息（偏暗 / 偏亮、偏暖 / 偏冷）；如果现有模型不输出，需要由模型作者补充。

---

## 7. 风险

| 风险 | 说明 | 对应需求 |
|---|---|---|
| 报告改写失真 | 报告由闭源 API 重写，可能加入模型没给出的判断，或把"偏低"说成"严重" | F8、F9；出现后可通过 F16 排查 |
| 分数换算不当 | 统一分制需要清楚每个模型分数的含义和范围；换算错了，分数会误导观众 | 依赖模型作者提供分数说明（信息清单暂缓，见 §9） |
| 模型本身出错 | 对外展示时模型判断有误，会直接影响观众对实验室能力的印象 | 暂无对应需求 |
| 被问到没有的能力 | 访客很可能问到噪声、模糊等目前没有模型的属性 | F3 |
| 接入门槛过高 | 如果作者本人接入很麻烦，新模型就进不来，框架失去"承载"的意义 | F15 |
| 缺少偏向信息 | 如果曝光、白平衡模型只输出分数、不输出偏向，F7 无法满足 | 见 §6 |
| 图片外传 | 使用闭源 API 时，图片可能会发送到外部服务 | 暂无对应需求 |

## 8. 待确认问题

1. **统一分制用哪种？** 0–100、1–5，还是"好 / 中 / 差"这样的等级？
2. **导出格式**：PDF、Word，还是图片？
3. **新增属性是否自动纳入"笼统评估"？** 例如以后接入噪声模型，用户笼统地问"评估质量"时要不要一起评？美学已明确只在点名时调用，其他属性是否也这样？
4. **批量评估要不要？** v1 中有批量筛查，本轮没有讨论。
5. **对外交流时由谁操作？** 实验室成员演示，还是访客自己上传图片使用？
6. **报告语言**：只要中文，还是需要中英文？
7. **作为大脑的闭源 API 是否需要能随时更换？** 比如换成更新、更强的版本。

## 附：与 v1 的主要变化

| 项目 | v1 | v2 |
|---|---|---|
| 定位 | 对外 demo + 影像诊断与调优顾问 | 承载实验室能力的框架；agent 能力够用即可 |
| 能力来源 | 实验室模型 | 实验室模型 + 闭源 API（作为大脑；实验室没有的属性以后可通过 skill 补充） |
| 需求拆解 | 核心能力（Must），结构化计划与澄清机制 | 只按属性简单拆；复杂拆解是伪需求，以后通过对话实现 |
| 覆盖属性 | 整体质量、美学、构图、曝光、对比度、白平衡、色彩 | 整体质量、曝光、对比度、白平衡、色彩；美学和构图以后作为扩展 |
| 调优建议 | 核心卖点，给出参数级调整建议 | 本阶段不做，只描述 |
| 分数呈现 | 默认展示档位，原始分数可展开查看 | 统一换算后展示，不展示原始分数 |

| 结论出处 | 可追溯到具体模型输出 | 不在结论旁标注 |
| 批量筛查、冲突消解、置信度、局部热力图、会话记忆 | 纳入不同阶段 | 本版不涉及（批量评估待确认） |
