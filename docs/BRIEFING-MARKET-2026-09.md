# IQA 商业竞品分析 · 汇报材料

> 2026-09 · 详细版见 `COMPETITIVE-RESEARCH.md`
> 调研范围：11 个类别、60 余个产品；73 处官方链接；24 处信息标注为待核实
> 方法：以厂商官网与官方文档为准；榜单类文章只用于发现线索，事实回官方页核实；厂商自述的性能数据已标注为「厂商声称」

---

## 第 1 页 · 三条核心结论

**一、"图像质量评价"在商业上不是一个市场，是四个客户完全不同的市场。** 把它们放在一起比较没有意义，先分清楚在说哪一个。

**二、"属性拆得细"和"说人话"之间有一道清晰的裂缝。** 拆得最细的（DXOMARK、Imatest、OFIQ）不生成自然语言；说人话的（Adobe Project Indigo、各类点评 App）属性很粗、也没有权威依据。中间是空的。

**三、对话式、能调度多个属性级模型并整合成报告的 IQA agent，商业上没有成品。** 最接近的是 Voxel51 FiftyOne 和 Cloudinary，但它们的 agent 调的是数据集操作和资产管理，不是一组画质模型。

## 第 2 页 · 四个市场

| 类型 | 问的问题 | 典型客户 | 代表产品 |
|---|---|---|---|
| **器件评测型** | 这台相机、这条 ISP 管线好不好？ | 手机厂、模组厂、汽车 Tier-1 | DXOMARK Analyzer、Imatest、iQ-Analyzer-X |
| **内容筛选型** | 这批图里哪些能用、哪些该丢？ | 内容平台、摄影师、AI 数据团队 | Aftershoot、Sightengine、FiftyOne |
| **采集合规型** | 这张图达标没有？不达标怎么重拍？ | 身份核验、KYC、银行、政务 | OFIQ、NFIQ 2、Regula、Veriff |
| **传输保真型** | 压完之后画质掉了多少？ | 流媒体、CDN、视频云 | SSIMPLUS、Beamr、Cloudinary |

四类的评价对象根本不同：第一类评的是**设备**，第二类评的是**图片能不能用**，第三类评的是**达不达标**，第四类评的是**压缩前后的差值**。

## 第 4 页 · A 类：影像实验室（属性做得最细的一档）

**DXOMARK** 同时做三件生意：公开榜单（品牌）、测试软硬件（产品）、调优咨询（服务）。

- **Analyzer** 覆盖 12 个测量类目，其中 **3A 拆成自动曝光、自动白平衡、自动对焦三项**；输出 Python 字典、Excel、HTML、PDF；分 FREE / GUI / **API（Python）** / PREMIUM 四档；全球已装 150 多个实验室。
- **公开榜单是一棵带权重的属性树**：总分 = 主摄 47% + 视频 27% + 长焦 13% + Bokeh 4% + 超广 3% + 视频长焦 5% + 视频超广 1%。Photo 下六个属性：**曝光、色彩、对焦、纹理、噪声、伪影**，Video 多一项防抖。每台设备拍摄分析约 **4000 张照片 + 200 分钟视频**，并用多文化焦点小组确定基准。
- **它的解释是分层的**：给工程师的软件里没有文字，给读者的评测文章里有大段解读和样张对比，给客户的建议做成**咨询服务**卖（四阶段 KPI 驱动的 ISP 调优）。
- **GEA（Golden Eye Assistant）**：官方定义为"AI 驱动的画质评估工具，让感知评价更快、更一致、可规模化"。**这是权威影像实验室把 AI 用于替代人眼主观评价最明确的公开信号。**是否基于大模型、是否输出文字、怎么定价，官方都没公开，**待核实**。
- **AIOP**：把人像拆成肤色还原、细节、虚化、曝光、色彩五维——"按场景重新组织属性"的范例。

**Imatest**：13 个以上质量因子，支持 30 多种标准图卡；**IT 产品线提供 C/C++ DLL、命令行、Python、.NET 四种接口**，专为无人值守产线设计；订阅与永久许可并行。**把"可编程接入"做成了单独的产品线并单独定价。**

**Image Engineering iQ-Analyzer-X**：9 个核心维度；**用 AI 做图卡检测和 ROI 定位——AI 用来提速测量流程，不用来做质量判断**；结果存数据库，支持跨实验室、跨时间比对。

**A 类的共性**：必须配硬件（测的是设备，没有受控输入就没有可比的测量）；可对比、可归档是刚需；解释和建议不做进软件，做成服务。

## 第 5 页 · B 类：云厂商画质 API（最"薄"的一类）

| 厂商 | 输出维度 |
|---|---|
| 阿里云 AssessSharpness | 单一清晰度评分 |
| **阿里云 EvaluateVideoQuality** | **国产里维度最全**：主观画质分；客观（清晰度、点状噪声、压缩噪声）；颜色（饱和度、丰富度、对比度、亮度）；瑕疵（场纹、划痕、卡帧、闪烁、黑屏花屏） |
| 阿里云 IMM / OSS | 只返回一个 0–1 综合分，内部含清晰度/噪声/色彩/曝光但**不分维度返回** |
| 腾讯云 AssessQuality | ClarityScore（0–100）+ AestheticScore（0–100）+ 五个布尔标记 |
| 百度智能云 | aesthetic、clarity 两个数（取值范围文档未明示，待核实） |
| 火山 veImageX | 大众美学、噪声强度、纹理丰富度、色调均衡四项 |
| 火山 VQScore | 无参考视频质量 0–100，对标 VMAF 但不需参考 |
| 华为云 | 清晰 / 模糊二分类 |
| **AWS Rekognition** | **亮度、锐度、对比度各 0–100**——国际大厂里唯一分维度的 |
| **Google Vision / Azure Vision** | **没有画质评分，也没有模糊检测** |

**三点观察**
1. 国产云的画质 API 都挂在内容审核、对象存储或媒体处理之下，是**附属能力，不是独立产品**。
2. **"清晰度 + 美观度"是国产云的事实标准双指标**（腾讯、百度都是这个形态）。
3. **曝光、白平衡、对比度基本不单独暴露**，被折叠进了综合分里。
4. Google 和 Azure 都判断"通用画质评分"不值得做成平台能力——**这本身是个很强的信号**。

## 第 6 页 · B 类：三家独立厂商的产品化思路

- **Sightengine**：给一个 0–1 的分，外加 sharpness / contrast / brightness 三项。没有文字解释，但文档给了**分段释义表**（<0.25 很差、0.45–0.60 尚可到好、>0.85 很好到完美），并建议用户自己设 0.5 阈值。**这是"最低成本的解释"：不写句子，但告诉你这个数该怎么读。** 免费 2000 次/月，超出 $0.002/次。
- **Everypixel**：0–100 分加 Poor / Good / Excellent 标签，而且**区分 UGC 和图库两个模型**——它承认"好照片"的标准依赖使用场景。$0.6/1000 次。
- **Clarifai**：没有现成的画质模型，但**"接入你自己的模型"就是公司定位**：从 HuggingFace 或本地上传，自动部署，可与 agent operators 组 workflow。

**B 类没有任何一家提供改进建议。**

## 第 7 页 · C 类：CDN（质量是手段，不是产品）

这一类的本质是：**画质评价不卖给客户，是内部用来自动决定压缩参数的**。客户买的是"小文件 + 看不出差别"。

- **Cloudinary** 的 `q_auto` 分 best / good / eco / low 四档，机制是启发式加试编码，再用自研的 **SSIMULACRA 2** 快速校验。这个指标**专门针对压缩伪影调过，已开源**。
- **Cloudinary 也是本次调研中 agent 化走得最远的图片厂商**：5 个 MCP Server（含 Analysis），可被 Cursor、Claude Desktop、Claude Code、VS Code 调用；2026 年 5 月推出 Cloudinary Agents。
- imgix、Uploadcare 都只给**档位名**，不给分数。

**产品提示：普通用户要的不是分数，是档位。** C 类唯一暴露给外部的"质量语言"就是 best / good / eco / low 这样的词。

## 第 8 页 · D 类：摄影工作流（商业闭环最成熟）

付费动机极其明确：一场婚礼 3000–5000 张，人工选片 6–10 小时。

| 产品 | 维度 | 输出 | 定价 |
|---|---|---|---|
| **Aftershoot** | 闭眼、模糊、重复 + 光线、背景干净度、构图 | 每张 1–100 分；分桶 Selected / Highlights / Closed Eyes / Blur / Duplicates；**模糊敏感度、重复相似度都有滑块** | **$10/月，张数不限** |
| **Narrative Select** | 对焦评分 0–100、眼睛状态、场景内按锐度排序 | 自动放大到人脸；无人脸时找主体 | $10–$60 分层 |
| **Imagen AI** | 选片 + 修图；**Personal AI Profile 用你自己 3000 多张历史修片训练，复刻你的风格** | 分组 + 高亮 | $0.05/张，年付 $59–$199/月 |
| **FilterPixel** | 单次检查全部八项信号，含**曝光质量（高光溢出、暗部死黑）** | 分数 + 分组；敏感度按题材可调 | $19 / $35 每月 |
| **Lightroom 辅助选片** | 主体对焦、眼部对焦、睁眼、曝光问题、误拍 | **可展开看每张的详细评分，理解 AI 为什么这么判** | 含在 CC 订阅内 |
| Photo Mechanic | **完全没有 AI 判断**，纯靠浏览速度 | — | 永久 $299 / $399 |

**四条洞察**
1. **全部不给改进建议。** 照片已经拍完了，建议没用；它们的价值是**替你做决策**。
2. **敏感度滑块是标配。** 厂商承认质量标准因人而异，把最终判断权还给用户。
3. **Imagen 的 Personal AI Profile 是"个性化"的最强形态**：不是接入你的模型，是用你的数据训一个你的模型。
4. **Photo Mechanic 到 2026 年还没有 AI，却依然活着而且不便宜**——说明"速度"本身就能独立售卖。

## 第 9 页 · E 类：视频质量

**卖一个可信的数**
- **IMAX / SSIMWAVE SSIMPLUS**：Viewer Score 0–100，每 20 分一档。**设备感知——同一段视频在电视和手机上给不同分数**，厂商称 PSNR 和 VMAF 都做不到。厂商声称与人眼相关性超过 90%、比 VMAF 快 10 倍（均为厂商声称，未独立验证）。**打法和 DXOMARK 同构：连续多年公开评测超级碗直播画质，把度量做成品牌。**
- **Beamr CABR**：在帧级挑"码率最低但感知不劣化"的编码，53 项专利，宣称码率降低 30–50%。质量度量不单独卖，是编码器的一部分。

**卖合规报告**
- **Interra BATON**：自动化音视频 QC，含基于神经网络的质量检查与伪影检测，**支持自动和人工混合 QC 在同一流程里**。

**卖运营可见性**
- **Mux Data**：Overall Viewer Experience 0–100，由播放成功率、启动时间、播放流畅度、视频质量**四个子分**构成；另有 **Negative Impact Score，直接排出哪个问题对整体体验伤害最大**。**这是"属性级 + 影响归因"在商业产品里最清晰的例子。**

## 第 10 页 · F 类：证件与身份（最重要的一类发现）

**这一类把"属性级 + 文字解释 + 改进建议"做到了商业上最成熟的程度。**

- **OFIQ / ISO 29794-5**：标准 2025 年 4 月发布，OFIQ 是德国联邦信息安全办公室 BSI 开发的开源参考实现。输出是**一个统一质量分（0–100，且被设计为可预测识别性能）加上 25 到 27 个独立质量分量**。
  **分量按来源分成两组**：
  - **采集相关**（光照、锐度、曝光）——由拍摄条件决定，**可以通过重拍改善**
  - **主体相关**（姿态、表情、遮挡、睁眼）——由被拍者决定
  **NIST 通过 FATE SIDD 按每个分量分别评测各家算法**——属性级评价在这个领域有独立第三方的分维度公开评测。
- **NFIQ 2**（指纹）：NIST 出品，开源。核心理念写进了标准：**质量分必须与实际识别性能校准过**，这样不同厂商的设备给出的质量值才能互相解读。
- **Regula**：三项检查（分辨率、对焦、眩光），**输出不是分数，是三值枚举**：达标 / 不达标 / 未执行检查。**面向决策而不是面向分析——用户要的是过还是不过，不是 0.73。**
- **Veriff、Jumio**：**在拍摄过程中实时反馈**，检测到模糊、眩光、遮挡后**当场告诉用户怎么修**。

**这一类为什么能做到解释和建议？三个前提缺一不可：**
1. **有标准**——ISO 把"什么算达标"写死了，解释才有依据
2. **有下游任务做锚**——质量分按"会不会影响识别率"校准，不是审美判断
3. **用户还在现场**——人还举着手机，建议立刻可执行，所以建议值钱

## 第 11 页 · 其余几类速览

**G 电商与图库**：不卖产品，卖准入规则，但**规则文档是本次调研中最接近"属性级 + 自然语言解释 + 改进建议"的公开材料**。Shutterstock 覆盖 14 项以上维度，**白平衡是独立的拒稿理由**；审稿人在 100% 原图比例下逐张看；拒稿时给出具体类别，每个类别还配一篇知识库文章讲怎么避免。
→ **当"质量"需要被仲裁时，人们最终依赖的是一份写清楚的、分维度的、带例子的自然语言规则，而不是一个分数。**

**H 数据集治理**：FiftyOne 检测六类问题（亮度、模糊、极端宽高比、信息熵异常、近似重复、完全重复），交互是**直方图 + 可拖动阈值滑块**；Cleanlab 七类，**同时给布尔判定和 0–1 严重度**。
→ **FiftyOne 有一套 agent skills 生态，其中就有画质相关的 skill，是"图像质量评估被封装成 agent skill"唯一明确的商业案例。**

**I 手机 ISP**：高通 Chromatix 是调优工具（暴露旋钮），联发科、虹软、Morpho 都没有独立的画质评估产品。
→ **调优工具由芯片厂给，评测工具由第三方给，两者刻意分离——裁判不该由选手来当。**

**J AIGC 评估**：Artificial Analysis 用同 prompt 并排盲测加 ELO，还**公布每 1000 张的推理成本**，画出质量–成本前沿。多模态 LLM-as-a-judge 已是评测 SaaS 的标准形态，**输出分数的同时必须给理由**——因为单一分数无法区分一批都很好看的图。

**K 消费级点评**（范围外的意外发现，也是最有参考价值的一类）：**Adobe Project Indigo** 2026 年 7 月更新，拍完给出覆盖取景、光线、色彩、情绪冲击的"专业意见"，并给重拍建议、在取景器里直接指出干扰物；底层用的是**谷歌的 Nano Banana 云端模型**。另有 PhotoCritic、Photo Critique、Evalens、PixMentor 等一批产品，形态一致：**属性级分数 + 每项一段文字 + 具体改进动作**，全部没有任何权威背书或准确率依据。

## 第 12 页 · 横向结论一：功能基础盘

**人人都有的五项**
1. 一个可排序、可卡阈值的**总分**
2. **批量处理**——没有一个产品只支持单图
3. **阈值或档位可调**——Sightengine 设阈值、Aftershoot 和 FilterPixel 给滑块、FiftyOne 给直方图滑块、Cloudinary 给四档。**这是共识，不是特色。**
4. 结果**可导出**或可编程接入
5. **清晰度 / 锐度**——唯一一个全类别、全产品都覆盖的属性

**少数派功能**：自然语言解释、改进建议、设备或场景感知的分数、影响归因、与下游任务性能校准、跨时间跨实验室对比、接入自定义模型、agent 接入。

## 第 13 页 · 横向结论二：解释和建议到底怎么做

**呈现形态有六档，商业产品各据一档**

| 档 | 形态 | 代表 |
|---|---|---|
| 1 | 一个数 | Sightengine、阿里云 IMM |
| 2 | 一个数 + 分段释义表 | Sightengine 文档、SSIMPLUS 五档 |
| 3 | 一个数 + 等级标签 | Everypixel、Cloudinary 四档 |
| 4 | **分维度的数 / 分桶** | **DXOMARK 属性树、Mux 四子分、Aftershoot 分桶、Lightroom 可展开评分** |
| 5 | 结构化枚举结论 | Regula 三值、OFIQ 分量向量、Shutterstock 拒稿类别 |
| 6 | 自然语言点评 + 具体动作 | Project Indigo、点评 App、图库知识库文章 |

- **B2B 工具类基本停在第 1 到 4 档**，解释以文档、图表、样张对比的形式存在于**软件之外**。
- **第 4 档是主流做法**：不写句子，把总分拆开，让用户自己看出问题在哪。**性价比最高。**
- **第 6 档只在两种场景出现**：用户还能重拍，或者产品卖的本来就是教学。

**关于建议的规律：价值完全取决于"还来不来得及"**
- 来得及 → 建议是核心卖点（Veriff、Jumio、Project Indigo、图库知识库）
- 来不及 → **商业产品一律不给建议，直接替你决策或直接替你修好**（Aftershoot 分桶、Cloudinary 自动优化）

## 第 14 页 · 横向结论三：客户到底为什么付钱

八类产品的付费动机抽出来只有五种：

1. **省掉人工逐张看的时间**（摄影工作流、数据集治理、平台机审）
   婚礼 3000 张选片 6–10 小时压到几十分钟。**这是整个市场最大、最刚性、变现最顺畅的需求。客户买的是时间，不是准确度**——所以敏感度滑块比高精度更重要，因为返工成本要低。
2. **要一个所有人都认的数，好让大家别吵了**（实验室、证件、视频度量）
   客户买的是**仲裁权和可比性**。这就是 ISO 和 NIST 背书在证件领域那么值钱的原因，也是 DXOMARK 的公开榜单能反过来支撑软件生意的原因。
3. **别让不合格的东西流到下游**（证件、图库、数据集、视频 QC）
   客户买的是**避免下游损失**。这类客户对"误杀"的容忍度低于"漏放"，所以他们要**可解释的拒绝理由**。
4. **在用户察觉不到的前提下少花钱**（CDN、视频编码）
   客户买的是**带宽和存储账单**。**这类客户永远不会为质量报告付费。**
5. **让我变得更好**（消费级点评）
   客户买的是**教学与反馈**。**这是唯一一个"解释和建议"本身就是全部商品的需求。**

**一个重要推论：前四种需求都不需要自然语言解释，只有第五种需要。商业界解释做得少，不是做不到，是大部分客户不为解释付钱。**

## 第 15 页 · 横向结论四：属性细度排名与商业模式

**属性级细度，从细到粗**
1. **OFIQ / ISO 29794-5**（人脸）：统一分 + 25 到 27 个分量，分采集相关与主体相关，有 NIST 分维度评测
2. **DXOMARK**：软件侧 12 个测量类目，榜单侧带权重的属性树；AIOP 按场景重新组织属性
3. **Imatest、iQ-Analyzer-X**：维度全但**刻意不给总分**——工程测量不做主观加权
4. **Mux Data**：四个子分 + 影响归因
5. **火山 veImageX 四项、阿里 EvaluateVideoQuality**：国产云里最细
6. **FiftyOne 六类、Cleanlab 七类**：属性级，但定位是异常检测而非质量评分
7. **腾讯、百度两项，Sightengine、Everypixel、阿里 IMM 一项**：最粗

**商业模式六种**：按调用量（云 API）、按张数或 credit（Imagen $0.05/张、Evoto 导出才扣费）、固定订阅不限量（Aftershoot $10/月，直接对打按张计费）、永久买断加年度维护（Imatest、Photo Mechanic，客户要求版本可冻结、结果可复现）、卖设备和实验室（DXOMARK，**硬件是护城河**）、卖服务和咨询（**这是"解释和建议"的商业化出口**）。

还有第七种：**开源 + 标准背书**（OFIQ、NFIQ 2、SSIMULACRA 2）——不直接变现，**通过成为事实标准获取话语权**。

**一个跨模式的规律：免费档在这个市场几乎是标配**，因为质量判断高度主观，客户必须先拿自己的图试过才敢买。

## 第 16 页 · 市场空白

1. **"属性级 + 自然语言解释"之间的裂缝。** 见第 1 页结论二。
2. **白平衡和对比度是"有行业需求、无公开 API"的维度。** 图库把白平衡列为独立拒稿理由，高通把 AWB 列为核心调优项，但**没有任何公开云 API 单独返回白平衡评价**。
3. **没有"多个专业 IQA 模型的统一承载平台"。** Clarifai 做通用模型托管但不懂画质；DXOMARK 和 Imatest 懂画质但只跑自家算法；FiftyOne 懂数据集但质量维度只有六个。
4. **对话式 IQA agent 是空白。**
5. **"质量分与下游任务性能校准"这个方法论，还没有扩散出生物识别领域。** 通用 IQA 的分数至今没有等价的锚。
6. **"属性来源归类"几乎无人借鉴。** OFIQ 的采集相关与主体相关二分法，是把诊断转成建议的关键一步，但只存在于人脸领域。
7. **AIGC 图像的传统失真维度评价需求正在消失，语义和结构维度的需求在上升。** 这会长期改变"图像质量"这个词的所指。
